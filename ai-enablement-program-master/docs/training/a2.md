# A2: Data Quality Panel, AI-Ready Repo And MCP Smoke Test

## Goal

Make the repository AI-ready for the selected track, add an internal catalog quality-control feature, and connect a basic read-only MCP for Confluence context.

## Feature

Add a block to `/catalog`:

```text
Data Quality
```

## Tasks: Product Functionality

Complete this part as one AI-assisted workflow. The student drives the workflow; AI performs research, proposes a plan, and implements only after the student approves the plan.

### Step 1: Research With AI

1. Ask AI to study:
   - metadata API;
   - `CatalogMetadata` frontend component;
   - `catalog/generated/catalog.json`.

2. Ask AI to explain:
   - where `/catalog` gets metadata;
   - which fields are already available;
   - whether the current backend metadata API is enough for the panel;
   - which frontend/backend files would need changes.

### Step 2: Approve The Plan

3. Ask AI to propose an implementation plan for `A2: Data Quality panel on /catalog` before changing files.

   The plan is for this required behavior:
   - add a `Data Quality` panel to `/catalog`;
   - show total products as a numeric count of all catalog products;
   - show warning count as a numeric count of catalog validation warnings/issues;
   - show products without price as a numeric count plus up to 5 affected product names with IDs;
   - show expired products as a numeric count plus up to 5 affected product names with IDs;
   - show products with validation issues as a numeric count plus up to 5 affected product names with IDs;
   - show source workbook as the workbook file name/path;
   - show imported at as the import timestamp/date;
   - for the three issue lists, show `0` and `No affected products` when the count is zero;
   - if there are more than 5 affected products, show 5 examples and a `+N more` note.

   If the current metadata API is not enough, the plan must cover:
   - extending the backend metadata DTO;
   - updating the mapper/service;
   - adding a backend test.

   The plan must list:
   - frontend files to change;
   - backend files to change, if metadata API changes are needed;
   - test or smoke-check scope;
   - risks and assumptions.

   Suggested prompt:

```text
Propose an implementation plan for A2: Data Quality panel on /catalog.

Required behavior:
- Add a Data Quality panel to /catalog.
- Show total products as a numeric count of all catalog products.
- Show warning count as a numeric count of catalog validation warnings/issues.
- Show products without price as a numeric count plus up to 5 affected product names with IDs.
- Show expired products as a numeric count plus up to 5 affected product names with IDs.
- Show products with validation issues as a numeric count plus up to 5 affected product names with IDs.
- Show source workbook as the workbook file name/path.
- Show imported at as the import timestamp/date.
- For the three issue lists, show 0 and No affected products when the count is zero.
- If there are more than 5 affected products, show 5 examples and a +N more note.

If the current metadata API is not enough, include backend metadata DTO, mapper/service and backend test changes in the plan.

The plan must list:
- frontend files to change;
- backend files to change, if metadata API changes are needed;
- test or smoke-check scope;
- risks and assumptions.

Do not change files yet.
```

4. The student reviews the plan and explicitly approves implementation.

### Step 3: Implement The Approved Change

5. After approval, ask AI to implement only the approved Data Quality panel plan. Do not change Excel files, generated catalog data, MCP configuration or AI workspace setup files as part of the product functionality change.

6. Ask AI to add or update a frontend test/smoke check.

### Step 4: Verify

7. Ask AI to run or document backend/frontend checks, then review the output yourself.

8. Review the final diff and confirm the change stays within A2 scope.

## Tasks: Mandatory Confluence MCP Smoke Test

MCP is mandatory on A2. The goal of this step is to learn how to give AI external project context through a tool, without writing to external systems.

1. Open the course page `04.1. Internal MCP Catalog: Jira, Confluence, Graylog, ATP`.

2. Connect a read-only MCP for Confluence/Jira in the selected tool:
   - Cline: through local Cline MCP Servers settings;
   - Cursor: through `.cursor/mcp.json` or user-level MCP config.

3. Do not commit real tokens, secret URLs or machine-specific config. If you need to show an example, use placeholders.

4. Check that AI sees Confluence tools, for example `confluence_search` and `confluence_get_page_content`.

5. Ask AI through MCP to read the Confluence course page and compare it with the local assignment. Use this prompt:

```text
Use Confluence MCP in read-only mode.
Find the A2 AI Workspace Setup page and the 04.1 Internal MCP Catalog page.
Compare them with docs/training/a2.md.
Tell me whether theory, practice and expected artifacts match.
Do not change anything in Confluence.
```

6. Create or ask AI to draft the artifact, then review it yourself:

```text
docs/training/artifacts/a2-mcp-confluence-smoke-test.md
```

7. In the artifact, describe:
   - which MCP was connected;
   - where the local config is stored, without secrets;
   - which prompt was used;
   - which MCP tools were called;
   - which Confluence pages were read;
   - what AI found when comparing Confluence and the local assignment;
   - confirmation that no write actions were performed;
   - security/privacy risks.

8. Verify that no real tokens, secret URLs, machine-specific MCP configs or external write actions are present in the final diff.

Graylog and ATP MCP can be explored after this step, but they do not block passing A2.
