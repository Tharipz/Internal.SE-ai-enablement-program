# A0: Catalog Understanding

## Goal

Understand the project through the selected AI IDE tool without changing code.

Supported tracks:

- Cline: use Cline Chat/Plan and do not move to implementation.
- Cursor: use Ask mode for read-only analysis; use Agent mode only to write the evaluation report.

## Tasks

1. Create the artifact file yourself:

```text
docs/training/artifacts/a0-catalog-understanding.md
```

2. Ask AI in the selected IDE tool to inspect the project in read-only mode and explain these sources:
   - `docs/catalog-analysis.md`;
   - `catalog/mobile-operator-catalog.xlsx`;
   - `catalog/generated/catalog.json`;
   - the `/shop` and `/catalog` pages.

   Suggested prompt:

```text
Use read-only analysis. Study docs/catalog-analysis.md, catalog/mobile-operator-catalog.xlsx,
catalog/generated/catalog.json, and the /shop and /catalog pages.
Explain the catalog entities, product types, Excel fields, UI differences, data quality issues,
and traceability fields. Do not change files.
```

3. Read AI's answer and verify it against the real files, JSON, Excel and UI pages. Do not copy unverified AI output into the artifact.

4. Ask AI to draft or update `docs/training/artifacts/a0-catalog-understanding.md` with these sections, then review and correct the content yourself:
   - which entities exist in the catalog;
   - which product types exist now;
   - which fields come from Excel;
   - how `/shop` differs from `/catalog`;
   - which data quality issues already exist;
   - what `sourceFile`, `sourceSheet`, `sourceRow`, `importedAt` mean.

5. In the same file, ask AI to add a section named `Prompts Used`, then fill or correct it yourself with 5 prompts that you actually used during A0. Do not let AI invent prompts you did not use.

6. In the same file, ask AI to add a section named `AI Answer Validation Checklist`, then review and adapt it yourself. Derive the checklist from the meaning of the BASS/Confluence A0 theory and this project: show which sources you personally used to verify the AI answers.

Suggested artifact structure:

```text
docs/training/artifacts/a0-catalog-understanding.md
  Catalog Entities
  Product Types
  Excel Fields
  /shop vs /catalog
  Data Quality Issues
  Traceability Fields
  Excel -> JSON -> API -> UI Flow
  Prompts Used
  AI Answer Validation Checklist
```

Minimum checklist example:

## AI Answer Validation Checklist

- [ ] Checked that AI referred to real project files instead of inventing paths or classes.
- [ ] Compared catalog answers with `docs/catalog-analysis.md`.
- [ ] Compared product types and fields with `catalog/generated/catalog.json`.
- [ ] Checked UI-visible fields through `/shop`, `/catalog` and frontend components.
- [ ] Compared Excel source sheets and traceability fields with the workbook/imported JSON.
- [ ] Separated direct Excel fields from derived fields and importer-generated metadata.
- [ ] Checked data quality issues through `validationIssues` and warnings.
- [ ] Confirmed that the Excel -> JSON -> API -> UI flow is described.
- [ ] Confirmed that A0 did not change backend, frontend, Excel or generated JSON.

7. Before evaluation, confirm that `a0-catalog-understanding.md` is complete and that no backend, frontend, Excel or generated JSON files were changed.

8. Only after the artifact is complete, ask AI to run `/evaluate-a0`. During evaluation, AI must create only `docs/training/artifacts/a0-evaluation-report.md`.

## Not Allowed

- Do not change backend.
- Do not change frontend.
- Do not change Excel or generated JSON.

## Acceptance Criteria

- File `docs/training/artifacts/a0-catalog-understanding.md` is created.
- At least 5 prompts are present.
- A result validation checklist is present.
- The document explains the Excel -> JSON -> API -> UI flow.
