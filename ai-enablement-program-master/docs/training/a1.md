# A1: Active Shop Filter

## Goal

Make the first small AI-assisted MR through Cline or Cursor.

## Feature

Add a filter to `/shop`:

```text
Active only
```

## Tasks

1. Ask AI to find the `/shop` implementation and explain the current frontend flow before edits.

   Suggested prompt:

```text
Find where /shop is implemented. Explain the components, data flow, existing filters,
and tests that may be affected. Do not change files yet.
```

2. Ask AI to propose an implementation plan for `A1: Active only filter on /shop` before changing files.

   The plan is for this required behavior:
   - `Active only = true` by default on `/shop`;
   - `EXPIRED` products are hidden on `/shop` while `Active only` is enabled;
   - the user can disable `Active only`;
   - after disabling it, expired offers are visible;
   - `/catalog` does not change.

   Use current demo data as a smoke-check example: `iPhone 11 64GB White` is an `EXPIRED` offer, so it must be hidden when `Active only` is enabled and visible after the user disables `Active only`.

   Suggested prompt:

```text
Propose an implementation plan for A1: Active only filter on /shop.

Required behavior:
- Active only is enabled by default on /shop;
- EXPIRED products are hidden on /shop while Active only is enabled;
- the user can disable Active only;
- after disabling it, expired offers are visible;
- /catalog behavior must not change.

Use current demo data as a smoke-check example: iPhone 11 64GB White is an EXPIRED offer, so it must be hidden when Active only is enabled and visible after the user disables Active only.

The plan must list affected files, expected behavior, test/smoke-check scope and risks.
Do not change files yet.
```

   - Cline: Plan & Act.
   - Cursor: Ask mode for research, Agent mode for implementation.

3. Review the plan. If it is correct, explicitly tell AI to implement the approved plan.

4. After approval, AI implements only the approved A1 plan. Do not change `/catalog`, backend code, Excel files or generated catalog data for A1.

5. Ask AI to add or update a frontend test/smoke test for the changed behavior.

6. Run or review the frontend checks and inspect the final diff. Confirm that backend, Excel and generated catalog data were not changed for A1.

7. Create or ask AI to draft the artifact, then review and correct it yourself:

```text
docs/training/artifacts/a1-ai-assisted-mr.md
```

8. In the artifact, record:
   - original prompt;
   - AI plan;
   - changed files;
   - tests;
   - verification results;
   - AI self-review;
   - what AI accelerated;
   - what was fixed manually.

9. Only after the feature, checks and artifact are complete, ask AI to run `/evaluate-a1`. During evaluation, AI must create only `docs/training/artifacts/a1-evaluation-report.md`.

## Acceptance Criteria

- `/shop` shows only `ACTIVE` products by default.
- `Active only` can be disabled.
- `/catalog` continues to show expired products through internal filters.
- A test or smoke check exists.
- The A1 artifact exists.

## Checks

```bash
cd frontend
npm test -- --watchAll=false
npm run build
```
