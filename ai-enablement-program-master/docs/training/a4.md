# A4: Catalog-Backed Sales Journey Agentic Workflow

## Goal

Create a reusable agentic workflow for adding a new customer-facing sales journey based on the Excel catalog.

On A4, it is important to show not only one feature, but a repeatable way of working:

```text
catalog data -> backend API -> frontend route -> cart/checkout demo -> tests -> review
```

## Repeatable Scenario

New customer-facing journeys that use the catalog regularly appear in the mobile operator portal:

- `/shop/bundles` - plan + phone / fiber + router;
- `/shop/add-ons` - add extra services to a plan;
- `/shop/devices-with-plan` - phone together with a postpaid plan;
- `/shop/fiber` - fiber plan + router + installation service;
- `/shop/compare` - compare plans;
- `/shop/promotions` - catalog-based promotions.

The A4 workflow must be reusable for these tasks. In this course, the example run for the workflow is Bundle Builder.

## Example Feature: Bundle Builder

Add the page:

```text
/shop/bundles
```

The user builds a bundle:

- postpaid plan + smartphone;
- fiber plan + router;
- optional accessory/service.

## Not Allowed

- Do not add DB.
- Do not add real payment/order submission.
- Do not add real auth.
- Do not make the workflow only for `/shop/bundles`; it must be reusable for other catalog-backed sales journeys.

## Acceptance Criteria

- Reusable workflow describes adding a catalog-backed sales journey.
- The workflow lists reuse examples: add-ons, devices-with-plan, fiber, compare, promotions or similar.
- `/shop/bundles` is implemented as an example run.
- `/api/catalog/bundles/options` works.
- Totals are calculated predictably.
- Incomplete selection state exists.
- Bundle is added to cart.
- For the Cline track: workflow `.clinerules/workflows/catalog-sales-journey.md` is created.
- For the Cursor track: command `.cursor/commands/catalog-sales-journey.md` and subagents in `.cursor/agents/` are created.
- The A4 artifact is created.
- Backend/frontend checks pass.

## Checks

```bash
cd backend
mvn test
mvn -q clean package
```

Use `mvn test` for final backend verification. Do not treat a failed Quarkus
dev-mode continuous-testing hot re-run as the final result. If dev mode shows
`Non-viable test classloader ... Is this a re-run of a failing test?`, stop
`mvn quarkus:dev` and run `cd backend && mvn test`.

```bash
cd frontend
npm test -- --watchAll=false
npm run build
```
